# Unit 01 — Software Design

Theoretical material corresponding to the first official topic of Software Development Process II: **Software Design**.

[Versión en español](README.es.md)

## Official Scope

According to the course syllabus, this unit covers:

- software design concepts
- design principles
- architectural design
- data design
- component design
- user interface design

## Current Contents

- `01-software-design-architecture-and-design-patterns-class-material.pdf`: Class 1 presentation introducing the course and reviewing software design, architecture, abstraction levels, and software quality attributes
- `02-software-design-concepts-and-principles-class-material.pdf`: Class 2 presentation focused on software design concepts, principles, quality attributes, design areas, and guidelines for good design

## Class 01 — Software Design, Architecture, and Design Patterns

The first class introduces the general direction of the course and places particular emphasis on the design stage of the software development lifecycle.

The material reviews:

- the software development lifecycle
- the role of software design
- abstraction levels in design
- architecture, subsystems, modules, design classes, and code
- software quality attributes
- the relationship between design, architecture, UML, patterns, and agile development

## Class 02 — Software Design Concepts and Principles

The second class develops the principles and concepts that guide a good software design.

The material covers:

- the purpose of software design
- the relationship between requirements, design, implementation, and testing
- the progression from architectural design to detailed design
- abstraction
- architecture
- design patterns
- modularity
- information hiding
- functional independence
- refinement
- object-oriented classes
- diversification and convergence during design
- examples and consequences of poorly designed systems
- accidental complexity and over-engineering
- data design
- architectural design
- interface design
- component design
- classical and modern software quality attributes
- governance and automation
- roles involved in software design
- design models and artifacts
- criteria for evaluating a design
- guidelines for producing high-quality designs

## Design Outputs

The unit identifies four main models that together form a software design specification:

1. data model
2. architecture model
3. interface model
4. component model

These models describe the system from complementary perspectives and progressively transform requirements into an implementable software solution.

## Design Quality

The material emphasizes that a good design should correctly implement the requirements while remaining understandable, complete, modular, maintainable, and appropriate to the characteristics of the system being developed.

Additional theoretical material will be incorporated as it is provided during the course.
